# ✅ 要件定義書

## Kindle 全ページスクリーンショット自動取得システム

---

## 1. システム概要

Kindle for Mac 上で開いている電子書籍を対象に、
**全ページを自動でスクリーンショット取得し、指定フォルダに連番で保存するツール**を構築する。

本システムは **Webアプリケーション形式のGUI自動化ツール**とし、
ユーザーが Kindle の表示状態を整えた後、ブラウザから操作する方式とする。
簡単なHTMLベースのUIを提供し、直感的な操作を可能にする。

---

## 2. 利用目的

* 自己学習・研究・メモ用途
* 必要なページの後処理（OCR・要約・検索など）への活用
* 書籍内容のデータ化の前処理

※ 本システムは **私的利用の範囲でのみ使用することを前提とする**

---

## 3. 対象環境（前提条件）

| 項目     | 内容                 |
| ------ | ------------------ |
| OS     | macOS              |
| Kindle | Kindle for Mac アプリ |
| 実行方法   | Python で Web サーバー起動 → ブラウザでアクセス |
| 画面状態   | フルスクリーン            |
| 操作方式   | 手動準備 → Web UI から実行        |
| 保存形式   | PNG → PDF            |
| 保存場所   | ローカルフォルダ           |
| ブラウザ   | Chrome / Safari / Firefox など |

---

## 4. 機能要件

### 4.1 スクリーンショット取得機能

* 全画面、または Kindle 表示領域のみのスクショ取得
* 1ページごとに1ファイル生成
* 取得画像は PNG 形式で保存

---

### 4.2 ページ送り自動化機能

* キーボード右矢印キーによるページ送り
* ページ切替後、指定秒数待機してから次のスクショを取得

---

### 4.3 Web UI機能

* **HTMLベースのシンプルなユーザーインターフェース**
  * 本の名前入力フィールド
  * 設定項目（ページ待機時間、PDF結合枚数、最大ページ数など）
  * 実行開始ボタン
  * 進捗表示（リアルタイム更新）
  * ログ表示エリア
  * 停止ボタン（実行中のみ表示）
* **レスポンシブデザイン**
  * シンプルで使いやすいUI
  * 進捗状況が視覚的に分かる表示

---

### 4.4 フォルダ作成・連番保存機能

* **実行時に本の名前を入力**
  * Web UIの入力フィールドから本の名前を入力
  * 入力された名前でフォルダを自動作成（存在しない場合）
* ファイル名形式
  `page_0001.png`
  `page_0002.png`
  …
* ページ順と保存順が完全一致すること
* すべてのスクリーンショットは指定フォルダ内に保存

---

### 4.5 実行制御機能

* Web UIから実行開始ボタンをクリック
* 実行開始前に数秒の開始待機時間を設ける（UIで設定可能）
* 実行開始後はユーザー操作不要（自動実行）
* ページ上限に到達したら自動終了
* 実行中は停止ボタンで中断可能

---

### 4.6 ログ表示機能

* 取得完了したページ番号をWeb UIにリアルタイム表示
* 進捗バーで全体の進捗状況を表示
* 異常終了時にどこで止まったか把握できること
* エラーメッセージを分かりやすく表示

---

### 4.7 PDF結合機能

* スクリーンショット取得完了後、自動でPDFに結合
* 結合する写真の枚数は設定可能（デフォルト値あり）
* 指定枚数ごとにPDFファイルを分割生成
  * 例：100枚ごとに `bookname_part1.pdf`, `bookname_part2.pdf` など
* PDFファイル名は本の名前（フォルダ名）を使用

---

### 4.8 PNG削除機能

* PDF作成完了後、自動でPNGファイルを削除
* PDF作成に失敗した場合はPNGを保持
* 削除前に確認メッセージを表示（オプション）

---

## 5. 非機能要件

| 項目  | 要件                   |
| --- | -------------------- |
| 再現性 | 同一環境で毎回同じ動作をする       |
| 安定性 | Kindle 側の軽微な遅延で停止しない |
| 保守性 | ページ数・待機秒数を簡単に変更可能    |
| 拡張性 | OCR・PDF化への拡張が可能であること |
| 安全性 | DRM解除を行わず、OSレベル操作のみ  |

---

## 6. システム構成

```
[ ユーザー ]
     ↓ Python でサーバー起動
[ Web サーバー（Flask/FastAPI）]
     ↓ ブラウザでアクセス
[ HTML UI（ブラウザ）]
     ↓ 本の名前・設定を入力
[ ユーザー入力（本の名前・設定）]
     ↓ 実行開始ボタンクリック
[ バックエンド処理開始 ]
     ↓
[ フォルダ作成（存在しない場合）]
     ↓
[ OSレベルのGUI操作（pyautogui）]
     ↓
[ Kindleアプリ ]
     ↓
[ 画面スクショ取得 ]
     ↓
[ 指定フォルダに連番PNG保存 ]
     ↓ 進捗をWeb UIに送信
[ 指定枚数ごとにPDF結合 ]
     ↓
[ PNGファイル削除 ]
     ↓
[ 完了メッセージをWeb UIに表示 ]
```

## 8. 操作フロー（ユーザー視点）

```
① ターミナルで Python サーバーを起動
② ブラウザで http://localhost:5000 にアクセス
③ Web UI が表示される
④ Kindle を起動
⑤ 対象の本を開く
⑥ フルスクリーン表示
⑦ 1ページ目に戻す
⑧ Web UI で本の名前を入力
⑨ Web UI で設定を確認・変更（必要に応じて）
⑩ 「実行開始」ボタンをクリック
⑪ 放置（自動実行）
⑫ Web UI で進捗状況をリアルタイム確認
⑬ 指定フォルダに連番画像が生成される
⑭ 最終ページ到達で自動停止
⑮ 指定枚数ごとにPDFに自動結合
⑯ PDF作成完了後、PNGファイルを自動削除
⑰ Web UI に完了メッセージ表示
```

---

## 9. 想定される制約・注意点

* Kindle の UI 変更により動作不能になる可能性あり
* ページめくり失敗時にスキップが発生する可能性あり
* システムスリープ中は実行不可
* Mac の解像度変更で座標がずれる可能性あり
* Web サーバーはローカルホストでのみ動作（セキュリティのため）
* ブラウザとKindleアプリを同時に表示する必要があるため、画面レイアウトに注意

---

## 10. 設定項目

| 項目 | 説明 | デフォルト値 |
| --- | --- | --- |
| ページ待機時間 | ページ送り後の待機秒数 | 2秒 |
| PDF結合枚数 | 1つのPDFに含める画像枚数 | 100枚 |
| 開始待機時間 | 実行開始前の待機秒数 | 5秒 |
| 最大ページ数 | 取得する最大ページ数（0=無制限） | 0 |

---

## 11. UIデザイン要件

### 11.1 画面構成

* **ヘッダー**
  * アプリ名「Kindle 自動スクショアプリ」
  * ステータス表示（待機中 / 実行中 / 完了 / エラー）

* **メインエリア**
  * **入力セクション**
    * 本の名前入力フィールド（必須）
    * 設定項目（ページ待機時間、PDF結合枚数、最大ページ数など）
  * **実行制御セクション**
    * 「実行開始」ボタン（大きなボタン）
    * 「停止」ボタン（実行中のみ表示）
  * **進捗表示セクション**
    * 進捗バー（0% - 100%）
    * 現在のページ数 / 総ページ数
    * 経過時間表示
  * **ログ表示セクション**
    * スクロール可能なログエリア
    * 最新のログが自動で表示される

* **フッター**
  * バージョン情報
  * 注意事項へのリンク

### 11.2 デザイン方針

* シンプルで直感的なUI
* モダンなデザイン（カード型レイアウトなど）
* 進捗状況が一目で分かる視覚的フィードバック
* エラー時は分かりやすいメッセージ表示
