# 出力ファイル仕様

## 出力先ディレクトリ構造

```
output/
└── [本の名前]/
    ├── page_0001.png
    ├── page_0002.png
    ├── page_0003.png
    ├── ...
    ├── [本の名前]_part1.pdf
    ├── [本の名前]_part2.pdf
    └── ...
```

## ファイル命名規則

### PNGファイル（スクリーンショット）

- **形式**: `page_XXXX.png`
- **XXXX**: 4桁の連番（0001から開始）
- **例**: 
  - `page_0001.png` - 1ページ目
  - `page_0002.png` - 2ページ目
  - `page_0100.png` - 100ページ目

### PDFファイル（結合後）

- **形式**: `[本の名前]_part[N].pdf`
- **[本の名前]**: ユーザーが入力した本の名前（ファイル名に使えない文字は `_` に置換）
- **[N]**: パート番号（1から開始）
- **例**:
  - `自分を育てる働き方ノート_part1.pdf` - 1〜100ページ
  - `自分を育てる働き方ノート_part2.pdf` - 101〜200ページ

## 出力先ディレクトリの設定

デフォルトの出力先は `output/` ディレクトリです。

`config.py` で変更可能：

```python
OUTPUT_DIR = "output"  # 出力先ディレクトリ
```

## ファイル名の安全化

本の名前に入力された以下の文字は、ファイル名に使えないため自動的に `_` に置換されます：

- `/` (スラッシュ)
- `\` (バックスラッシュ)
- `:` (コロン)

**例**:
- 入力: `本/タイトル:サブタイトル`
- 出力ディレクトリ: `output/本_タイトル_サブタイトル/`

## PDF分割の仕組み

### デフォルト設定

- **1つのPDFに含まれる画像枚数**: 100枚（`config.PDF_PAGES_PER_FILE`）
- **分割例**:
  - 150ページの場合 → `part1.pdf` (1-100ページ) + `part2.pdf` (101-150ページ)
  - 250ページの場合 → `part1.pdf` (1-100ページ) + `part2.pdf` (101-200ページ) + `part3.pdf` (201-250ページ)

### カスタマイズ

`create_pdf.py` を使用する場合：

```bash
# 50枚ごとに分割
python create_pdf.py --dir "output/本の名前" --name "本の名前" --pages 50
```

## ファイルの保存順序

1. **スクリーンショット取得時**
   - PNGファイルが連番で保存される
   - `page_0001.png` → `page_0002.png` → `page_0003.png` ...

2. **PDF結合時**
   - PNGファイルを連番順に読み込み
   - 指定枚数ごとにPDFに結合
   - 同じディレクトリにPDFファイルを保存

3. **PNG削除時**（オプション）
   - PDF作成成功後、PNGファイルを削除
   - PDFファイルのみが残る

## 出力例

### 実際の出力構造

```
output/
└── 自分を育てる働き方ノート/
    ├── page_0001.png
    ├── page_0002.png
    ├── page_0003.png
    ├── ...
    ├── page_0150.png
    ├── 自分を育てる働き方ノート_part1.pdf  (1-100ページ)
    └── 自分を育てる働き方ノート_part2.pdf  (101-150ページ)
```

## ファイルサイズの目安

- **PNGファイル**: 約500KB〜2MB/ページ（画面解像度による）
- **PDFファイル**: 約50MB〜200MB/100ページ（画像の圧縮率による）

## 注意事項

1. **同じ本の名前で実行した場合**
   - 既存のディレクトリに上書きされる可能性があります
   - 既存のファイルは削除されませんが、同じファイル名の場合は上書きされます

2. **ディスク容量**
   - 大量のページを取得する場合、十分なディスク容量を確保してください
   - 100ページで約100MB〜200MBの容量が必要です

3. **PNGファイルの削除**
   - PDF作成後にPNGを削除すると、容量を大幅に節約できます
   - 削除後はPDFファイルのみが残ります

## 出力ファイルの確認方法

### ターミナルで確認

```bash
# 出力ディレクトリの内容を確認
ls -lh output/本の名前/

# PNGファイルの数を確認
ls output/本の名前/*.png | wc -l

# PDFファイルを確認
ls -lh output/本の名前/*.pdf
```

### Finderで確認

1. `output` フォルダを開く
2. 本の名前のフォルダを開く
3. PNGファイルとPDFファイルが表示される

## ディレクトリ整理の方法

### 現在の構造（推奨）

```
output/
└── [本の名前]/
    ├── page_*.png
    └── [本の名前]_part*.pdf
```

**メリット**:
- シンプルで分かりやすい
- 本ごとにすべてのファイルが1つのフォルダにまとまる
- 検索しやすい

### 整理方法の提案

#### 1. 日付で整理する方法

```
output/
├── 2024/
│   ├── 01/
│   │   └── [本の名前]/
│   └── 02/
│       └── [本の名前]/
└── 2025/
    └── 01/
        └── [本の名前]/
```

**実装方法**: `config.py` で日付を追加
```python
from datetime import datetime
OUTPUT_DIR = f"output/{datetime.now().strftime('%Y/%m')}"
```

#### 2. PNGとPDFを分ける方法

```
output/
└── [本の名前]/
    ├── png/
    │   ├── page_0001.png
    │   └── ...
    └── pdf/
        ├── [本の名前]_part1.pdf
        └── ...
```

**メリット**: ファイルタイプで分けられる

#### 3. 完了済みをアーカイブする方法

```
output/
├── active/          # 作業中
│   └── [本の名前]/
└── archive/         # 完了済み
    └── [本の名前]/
```

**メリット**: 作業中と完了済みを分けられる

#### 4. カテゴリで整理する方法

```
output/
├── 技術書/
│   └── [本の名前]/
├── ビジネス書/
│   └── [本の名前]/
└── 小説/
    └── [本の名前]/
```

**メリット**: ジャンルで分類できる

### 推奨される整理方法

**現在の構造（本の名前で整理）が最もシンプルで推奨**です。

理由：
- ✅ 本ごとにすべてのファイルが1箇所にまとまる
- ✅ 検索が簡単（本の名前で検索）
- ✅ 管理が容易
- ✅ 削除も簡単（フォルダごと削除）

### 大量の本を管理する場合

本が増えてきた場合は、以下の方法を検討：

1. **年で大分類**:
   ```
   output/
   ├── 2024/
   │   └── [本の名前]/
   └── 2025/
       └── [本の名前]/
   ```

2. **完了した本をアーカイブ**:
   ```
   output/
   ├── [本の名前]/        # 作業中
   └── archive/
       └── [本の名前]/    # 完了済み（PDF作成後）
   ```

3. **PNG削除で容量削減**:
   - PDF作成後、PNGを削除することで容量を大幅に削減
   - PDFのみ残すことで管理も簡単
